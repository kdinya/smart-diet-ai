# План оптимізації репозиторію Smart Diet AI (Тимчасовий файл)

> **Примітка для ШІ-асистентів:** Цей файл є тимчасовим трекером поетапної оптимізації структури репозиторію.
> Мета: прискорити внесення змін, кардинально знизити витрату лімітів контексту/токенів та виключити ризик синтаксичних і логічних помилок.
> **Критичні інваріанти:**
> 1. Жодні зміни не повинні порушувати існуючий UI/дизайн, втрачати збережені дані користувачів чи ламати бізнес-логіку.
> 2. Версію додатку (`APP_VERSION`), релізи та теги без прямої команди користувача **не змінювати**.
> 3. При виконанні чергового етапу оновлюйте відповідний пункт на `[x] Виконано` і зберігайте опис того, що було зроблено.
> 4. Після завершення всіх запланованих етапів цей файл буде видалено.

## Прогрес оптимізації

- [x] **Етап 1: Нормалізація `js/i18n.js` та миттєвий юніт-тест перевірки паритету**
  - **Проблема була:** Весь словник (971 ключ, 170 КБ) зберігався в один-єдиний нерозривний рядок довжиною 169 692 символи. Будь-яке додавання чи редагування ключа змушувало ШІ зчитувати й модифікувати гігантський рядок із високим ризиком пошкодження сусідніх ключів та перевитрати токенів.
  - **Що зроблено:**
    - `js/i18n.js` відформатовано з чистими відступами (один ключ на рядок). Користувачі та ШІ тепер бачать точний і зрозумілий diff окремих рядків.
    - Створено надшвидкий юніт-тест `tests/unit/i18n.test.mjs`, який за ~15 мс перевіряє 100% паритет ключів між `en` та `uk`, відсутність порожніх значень та відповідність FAQ-структур.
    - Тест інтегровано в `npm run test:unit` у `package.json` та в GitHub Actions CI workflow (`.github/workflows/ci.yml`).
    - Оновлено версію кешу сервіс-воркера в `sw.js` (`smart-diet-shell-v294`).
  - **Результат:** Зменшення витрати токенів при редагуванні перекладів у 10+ разів; помилки паритету локалізації виявляються локально за мілісекунди без тривалого очікування CI.

- [x] **Етап 2: Форматування блоків розмітки в `index.html` — виконано**
  - **Проблема була:** Ключові секції онбордингу, налаштувань і цілі ваги були записані довгими однорядковими HTML-блоками.
  - **Що зроблено:** Відформатовано лише ці три блоки з відступами між структурними елементами. Перевірено, що послідовність HTML-тегів з усіма атрибутами та весь непорожній текст у кожному блоці повністю збігаються з початковими.
  - **Результат:** Блоки зручніше читати й змінювати; розмітка, видимий текст, логіка, дані, стилі та версія додатку не змінювалися.

- [x] **Етап 3: Модуляризація клієнтської логіки з `index.html` (винесення `js/ecobot.js`)**
  - **Проблема:** У `<script>` всередині `index.html` знаходилося ~500 КБ JavaScript (близько 600 функцій). ШІ змушений був аналізувати монолітний файл для будь-якої зміни логіки помічника та діалогів.
  - **Що виконано:**
    - Винесено візуального помічника EcoBot, Spine-анімації, комікс, діалогові репліки, FAQ та жестове керування в окремий ванільний модуль `js/ecobot.js` (~57 КБ, без білд-степів і сторонніх бібліотек).
    - Додано юніт-тести чистої логіки помічника в `tests/unit/ecobot.test.mjs` (періоди доби, пози помічника, піжамний режим, розрахунок форми хмаринок SVG, FAQ-рендер).
    - Оновлено `package.json` (`test:unit`), `sw.js` (кеш `smart-diet-shell-v295` та додавання в `SHELL`), `.github/workflows/ci.yml` (`node --check js/ecobot.js` та запуск `ecobot.test.mjs`).
  - **Результат:** `index.html` зменшився на ~56 КБ (~108 рядків складного коду), логіка помічника повністю ізольована та покрита швидкими юніт-тестами. Подальші кроки етапу (`js/storage.js`, `js/sync.js`) виконуватимуться наступними безпечними ітераціями.

- [ ] **Етап 4: Декомпозиція гігантського `tests/smoke.ui.spec.js` (6 110 рядків)**
  - **Проблема:** Файл `smoke.ui.spec.js` містить понад 6 тисяч рядків, що уповільнює пошук і навігацію тестів.
  - **Що заплановано:** Розподілити тести за доменними сутностями (наприклад, `smoke.diary.spec.js`, `smoke.settings.spec.js`, `smoke.stats.spec.js`).
  - **Результат:** ШІ запускає та перевіряє лише релевантний тестовий набір, прискорюючи діагностику.

- [x] **Етап 5: Скрипт комплексної експрес-перевірки `npm run check`**
  - **Що зроблено:** `scripts/check.mjs` (без залежностей, ~1 с) перевіряє валідність JSON (`manifest.json`, `package.json`), синтаксис вбудованих скриптів `index.html`, `sw.js`, `js/*`, `tests/*.js` і `scripts/*`; що кожен локальний `<script src>` та `<link href>` з `index.html` є в `SHELL` сервіс-воркера, а кожен запис `SHELL` існує; що при зміні файлу з `SHELL` відносно `origin/main` піднято `CACHE`; запускає всі `tests/unit/*.test.mjs`.
  - **CI:** крок «Fast checks» у `.github/workflows/ci.yml` тепер викликає цей же скрипт (у CI без `origin/main` перевірка версії кешу пропускається).
  - **Результат:** помилки синтаксису, забутий файл у `SHELL` чи забута версія кешу виявляються до коміту.
