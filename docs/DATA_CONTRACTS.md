# Контракти даних та сценарії розрахунків (Data Contracts & Invariants)

Цей документ є обов'язковим джерелом істини для розробників та AI-асистентів. Він описує структури даних, правила розрахунків харчової цінності та матрицю сценаріїв, які суворо заборонено порушувати.

---

## 1. Моделі даних (Data Models)

### 1.1. Простий продукт (Simple Product)
Базовий харчовий продукт із фіксованими значеннями на задану вагу (зазвичай 100 г).
```json
{
  "id": "uuid-v4",
  "name": "Назва продукту (max 120 chars)",
  "grams": 100,
  "kcal": 250,
  "protein": 10.5,
  "fat": 5.0,
  "carbs": 30.0,
  "verified": true,
  "note": "Користувацька примітка (до 2000 символів, опціонально)",
  "companions": [],
  "components": []
}
```

### 1.2. Продукт із додатками (Product with Add-ons / Companions)
Продукт (наприклад, кава або вівсянка), до якого користувач може додавати супутні продукти (молоко, цукор, сироп).
- Поле `companions` містить посилання на ID супутніх продуктів із каталогу/списку продуктів:
```json
{
  "id": "uuid-v4-main-product",
  "name": "Кава американо",
  "grams": 150,
  "kcal": 2,
  "protein": 0.2,
  "fat": 0.0,
  "carbs": 0.3,
  "companions": [
    {
      "id": "uuid-v4-addon-milk",
      "grams": 50,
      "on": true
    },
    {
      "id": "uuid-v4-addon-sugar",
      "grams": 5,
      "on": false
    }
  ]
}
```
**Критичне правило розрахунку:**
- Кількість додатків (`companions`) **НЕ залежить** від кількості порцій основного продукту!
- Враховується рівно стільки грамів додатка, скільки вказано користувачем, навіть якщо основного продукту додано 2 чи 3 порції.

### 1.3. Складна страва (Composite Dish / Ingredients)
Страва, створена з кількох інгредієнтів (наприклад, борщ, салат, сирники).
- Складна страва містить масив `components`, де кожен інгредієнт зберігає свої параметри та стан активності:
```json
{
  "id": "uuid-v4-dish",
  "name": "Борщ український",
  "grams": 450,
  "kcal": 280,
  "protein": 12.0,
  "fat": 10.0,
  "carbs": 24.0,
  "verified": true,
  "components": [
    {
      "id": "uuid-v4-beet",
      "name": "Буряк варений",
      "grams": 150,
      "kcal": 65,
      "protein": 2.5,
      "fat": 0.2,
      "carbs": 14.0,
      "enabled": true
    },
    {
      "id": "uuid-v4-pork",
      "name": "Свинина нежирна",
      "grams": 100,
      "kcal": 160,
      "protein": 18.0,
      "fat": 9.5,
      "carbs": 0.0,
      "enabled": true
    },
    {
      "id": "uuid-v4-sour-cream",
      "name": "Сметана 15%",
      "grams": 30,
      "kcal": 48,
      "protein": 0.8,
      "fat": 4.5,
      "carbs": 1.1,
      "enabled": false
    }
  ]
}
```
**Критичні правила для складної страви:**
1. **Без порцій:** У складній страві використовуються **тільки грами**, поля порцій відсутні (`portions` не використовується).
2. **Динамічний перерахунок активних складників:** Тільки ті інгредієнти, у яких `enabled !== false` (позначені чекбоксом), беруть участь у розрахунку загальної ваги, калорій, білків, жирів і вуглеводів. Вимкнений інгредієнт не додає своїх показників до підсумку.
3. **Пропорційне масштабування:** При зміні загальної ваги страви (`grams`) вага кожного активного інгредієнта пропорційно перераховується.
4. **Редагування окремого інгредієнта:** При зміні ваги окремого інгредієнта через кнопку розгортання, його параметри динамічно перераховуються й оновлюють загальні параметри страви.

### 1.4. Запис у щоденнику прийомів їжі (Diary Entry)
```json
{
  "id": "uuid-v4",
  "name": "Назва запису або страви",
  "meal": "breakfast" | "lunch" | "dinner" | "snack",
  "grams": 250,
  "kcal": 320,
  "protein": 15.2,
  "fat": 8.1,
  "carbs": 38.0,
  "date": "YYYY-MM-DD",
  "portions": 1.5,
  "snackId": "uuid-v4 (тільки для snack)",
  "mealOrder": 0,
  "components": [ ... ]
}
```
**Критичний інваріант для запису щоденника:**
- Якщо це складна страва (`isCompEntry`), поле `portions` **видаляється** (`delete entry.portions`). Складна страва в щоденнику живе виключно у грамах.

## 2. Матриця критичних сценаріїв (Regression Invariants)

| Сценарій | Очікувана поведінка | Чого робити категорично не можна |
| :--- | :--- | :--- |
| **2.1 порції простого продукту** | Калорії, БЖВ та грами множаться на 2.1 | Округляти порції до цілого або ігнорувати десяткові дроби |
| **Вимкнення інгредієнта у складній страві** | Знята галочка виключає його показники із загальних ккал/БЖВ/ваги страви | Видаляти інгредієнт зі страви або затирати його початкову вагу |
| **Зміна загальної маси складної страви** | Вага всіх активних інгредієнтів масштабується пропорційно новій загальній вазі | Додавати поле порцій або масштабувати вимкнені інгредієнти |
| **Продукт із додатками** | Додатки враховуються як фіксована додаткова вага до страви | Множити вагу додатка на кількість порцій основного продукту |
| **Редагування інгредієнтів складної страви** | Розгортання картки інгредієнта відкриває інлайн-поле введення грамів | Відображати олівець або кнопку видалення біля інгредієнтів |
| **Збереження даних при перезавантаженні** | Усі продукти, щоденник та вага залишаються в `smartdiet-v1` у localStorage | Змінювати ключі сховища, затирати поля або скидати стан |
| **Синхронізація з Supabase** | Дані з локальної черги надсилаються до хмари без втрат | Вважати невдалу синхронізацію успішною чи видаляти невідправлені черги |

## 3. Маршрутизація задач для AI (Task-Based Routing)

Щоб майбутні зміни використовували мінімум токенів і не завантажували весь проєкт:

1. **Завдання щодо складних страв, додатків та каталогу:**
   - Читати: `docs/DATA_CONTRACTS.md`
   - Тести: `tests/smoke.products.spec.js` (запуск: `npm run test:smoke:products`)
   - Не зачіпати: анімацію Spine, логіку авторизації, AI-дієтолога, графіки ваги.

2. **Завдання щодо щоденника та прийомів їжі:**
   - Читати: блок щоденника в `index.html`
   - Тести: `tests/smoke.diary.spec.js` (запуск: `npm run test:smoke:diary` або `npm run test:smoke:ui`)
   - Не зачіпати: схему бази даних Supabase.

3. **Завдання щодо розрахунків (БЖВ, порції, калорії):**
   - Перевіряти проти формул у цьому документі.
   - Запускати тільки релевантні тести продуктів/щоденника.
