# Smart Diet AI

Мобільний вебзастосунок українською для розрахунку порцій, щоденника харчування та відстеження ваги. Інтерфейс зосереджений на ШІ-дієтологові та практичних розрахунках грамів, без функцій попереднього продукту, окрім корисних для цієї задачі.

> Це інструмент самоспостереження, а не медична порада. ШІ може помилятися; перевіряйте харчові значення за етикеткою або надійною базою, особливо при алергіях, захворюваннях, вагітності чи розладах харчової поведінки.

## Функції

- ШІ-чат для приблизного розрахунку грамів під ціль калорій або БЖВ через власний ключ Google Gemini чи OpenAI.
- Ручний розрахунок грамів із відомого значення макронутрієнта на 100 г.
- Щоденник продуктів за датами, калорії та БЖВ.
- Історія ваги й прості графіки тенденцій.
- Локальний режим для швидкого тестування та експорт локальних даних у JSON.
- Опційне підключення Supabase Auth + PostgreSQL для персональних даних у хмарі та входу з різних пристроїв.
- Адаптивний PWA-інтерфейс для телефона й комп'ютера.

## Запуск

Статичний сайт: відкрийте `index.html` у браузері або запустіть простий локальний сервер:

```bash
python3 -m http.server 8080
```

Відкрийте `http://localhost:8080`. Для встановлення PWA потрібен HTTPS (або localhost).

## Налаштування AI

У **Налаштування → AI-провайдер** оберіть Gemini або OpenAI та введіть свій API-ключ. Для Gemini отримайте ключ у [Google AI Studio](https://aistudio.google.com/apikey). Ключ зберігається в `localStorage` цього браузера й використовується з клієнта напряму. Це зручно для персонального тестування, але не є сховищем секретів: власник пристрою/розширення браузера можуть отримати доступ до ключа, а мережевий запит іде безпосередньо провайдеру. Не вводьте ключ на спільних пристроях; не комітьте його у GitHub і не пересилайте у чат. Ключі не синхронізуються між пристроями. Для публічного продукту зручніше винести виклики AI у захищений серверний endpoint і продумати тарифування/ліміти.

Квоти безкоштовного AI залежать від моделі, регіону та актуальних правил провайдера і можуть змінюватися. Перевіряйте ліміти в консолі постачальника; безкоштовний доступ не гарантований для кожної моделі.

## Supabase: синхронізація між пристроями

1. Створіть проєкт у [Supabase](https://supabase.com/).
2. Відкрийте SQL Editor та виконайте `supabase/schema.sql`.
3. У застосунку зайдіть у **Налаштування**, введіть Project URL і публічний `anon`/publishable key з налаштувань API проєкту, натисніть **Підключити Supabase**.
4. Створіть акаунт або увійдіть тим самим email/паролем на кожному пристрої.
5. Переконайтеся, що RLS увімкнено. SQL у файлі створює політики, які дозволяють користувачу працювати лише зі своїми рядками.

**Ніколи не вставляйте `service_role` key у браузер, GitHub, Vercel public variables чи цей код.** Публічний anon/publishable key призначений для браузерного клієнта лише разом із коректними RLS-політиками. Дані в хмарі зберігаються в проєкті Supabase, окремо від хостингу сайту. Зробіть резервні копії; жоден безкоштовний хмарний сервіс не є гарантією безстрокового зберігання.

Зараз профільні цілі та AI-ключ зберігаються локально в браузері. Харчовий щоденник і вага синхронізуються через Supabase після входу. Для відновлення AI-ключа на новому пристрої потрібно ввести його там окремо.

## Деплой з GitHub

### Vercel

1. Імпортуйте `kdinya/smart-diet-ai` у Vercel через **Add New → Project**.
2. Framework preset: **Other**; Build Command і Output Directory залиште порожніми/за замовчуванням для статичного сайту.
3. Натисніть Deploy. Подальші коміти у гілку `main` запускають автоматичний деплой.

### Netlify

Імпортуйте репозиторій через **Add new site → Import an existing project**. Для цього статичного проєкту команда збірки не потрібна, директорія публікації — корінь репозиторію (`.`). Коміти у production branch запускають автоматичне оновлення.

## Приватність і обмеження

- Локальний режим зберігає щоденник у сховищі браузера; очищення даних браузера може видалити локальні записи. Експортуйте резервну копію.
- Після входу через Supabase записи харчування і ваги зберігаються в акаунті користувача та можуть завантажуватися на інші пристрої.
- Не зберігайте паролі або секретні серверні ключі в репозиторії. Не додавайте реальні персональні дані у тестові коміти.
- На цьому етапі AI API-ключ зберігається лише локально, не шифрується на сервері й не переноситься між пристроями.
- Статистика обчислюється за внесеними вручну значеннями, тому точність залежить від повноти журналу.
